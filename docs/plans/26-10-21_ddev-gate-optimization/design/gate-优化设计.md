# ddev-gate 价值优先改造设计

> 输入：`docs/report/26-10-21_ddev-gate历史评审分析.md`（466 份真实评审报告）
> 原则：把预算花在只有模型能做对的判断上；能用脚本判定的，不进入审查对话。
> 备注：`skill-optimizer` 的正式管线本轮不可用（`.skillopt/pending` 为空，无 pending signal），因此改用历史日志证据驱动；改完后再用 `skill-recorder` 记录信号。

## 1. 价值定位：真正值钱的是五类判断

从 466 份报告反推"哪一类的结论改变过代码/拦住过问题"：

| # | 价值点 | 为什么模型必须参与 | 历史证据 |
|---|---|---|---|
| V1 | **越界与漏改**：实际改动 vs spec/detail 声明文件表 | 脚本能列出 diff 文件，但"这个文件该不该动"要读文档语义 | 62 份报告以"影响面超出声明范围"立案；越界是 blocked 的常见单点理由 |
| V2 | **三方口径矛盾**：spec / detail / 代码 / 注释 互相打架 | 文档是自然语言，冲突检测与"定稿建议"只能模型做 | 155 份报告产出偏离清单；84 份报告涉及口径矛盾；blocked 条目首位就是"spec 表述互相矛盾需定稿唯一口径" |
| V3 | **假修复 / 假通过识别** | 需要在"声明"与"代码事实"之间做证据对账，还要设计探针反证 | 抓到"声明 59 处已统一，实测仍余 14 处"；抓到"删掉整个文件头注释块后脚本仍 PASS"（假通过探针） |
| V4 | **行为级缺陷**：OOM/边界/返回值/并发/未实现/错误路径 | 需要读数据流与生命周期 | 34 条 HIGH 属行为类（如 `puzzle->num=2` 生效后 malloc 失败导致确定性 NULL 写） |
| V5 | **注册点/分发表/枚举映射齐备** | 需要跨文件反查"新增项是否被接上" | 42% 报告提及；漏注册是硬缺陷且静默失效 |

**判据**：这五类的共同点是"脚本最多给线索，结论必须读文档+读代码+交叉对账"。这正是 subagent 该干的活。

### 与之对照：高产出、低价值的三类

| 维度 | 体量证据 | 结论 |
|---|---|---|
| 注释机械项（术语泄漏 125、冗余 53、英文 52、缺头 50） | 清理清单里注释类 ≈130 条，占大头 | 99% 可脚本判定，不该占报告篇幅 |
| 死代码 / 魔术数字 / 过长函数 / 格式 | 34 / 31 / 15 条 | 都是"清单项"，不阻塞、可批量、可脚本 |
| 存量坏味道 | 140 份报告讨论"存量/非本轮/建议不改" | 与门禁目标无关，应默认排除 |

## 2. 新流程：三道闸，预算 3 轮

```
改动完成
  ↓
P0 机械闸（主 agent 跑脚本，0 模型，不进对话）
   ├─ 范围对账：git diff --name-only vs spec/detail 声明文件表
   ├─ 注释机械项：@file/@brief、英文注释、术语泄漏、#if 0、注释掉代码、冗余 extern、注释与代码不一致（可正则部分）
   ├─ 卫生项：裸 printf、魔术数字、过长函数、零引用符号
   └─ 注册点清单：新增 enum/事件表项 vs 注册点命中
   → 有 FAIL：主 agent 先修，**不派 subagent**
   → 全 PASS：进入 P1
  ↓
P1 语义闸（A 一致性 + B 行为评审，并行、只读，各 1 个 subagent）
   A：只做 V1/V2/V5（越界、口径矛盾、注册点语义）
   B：只做 V3/V4 + 机械闸结果解读（假修复、行为缺陷、脚本未覆盖的语义注释问题）
   输出：机读首行 + 分级 + 证据级别
  ↓
P2 收口闸（增量复审，最多 2 次）
   A 复跑条件：仅当改动触及架构面（模块边界/公共接口/依赖方向/状态所有权）
   B 复审范围：本轮 diff + 上一轮未闭环项 ID（禁止全量重扫）
   终止条件：无 CRITICAL/HIGH + 本轮无代码修改
  ↓
超预算（3 轮）：输出 need-info + 遗留清单，交用户裁决
```

关键改动全部服务于一件事：**让 P1 只处理"只有模型能判断"的部分**。

## 3. 具体文件改动

### 3.1 SKILL.md

**移除/降权**

| 现状 | 改成 |
|---|---|
| 「注释问题分级（与 ddev-comment-gen 共用口径）」整节 | 移入 `references/acceptance-checklist.md`；主流程只留"注释机械项见机械闸，语义项见 V3" |
| 步骤 5「MEDIUM/LOW 注释缺口同轮补齐、冗余注释同轮删除」 | 改为"MEDIUM/LOW 只入 backlog，终轮一次性处理，不作为重跑触发条件" |
| 步骤 6「只要发生任何修改就重跑 A+B」 | 改为增量复审：B 只审 diff+未闭环；A 仅架构面变更才复跑 |
| 「清理建议清单」由 B 在每轮输出 | 只在终轮输出一次；B 不再承担 ddev-clean 的逐条清单职责 |
| 步骤 0 Stop Gate 全程逐项 | 保留，但移出"每轮"语义——只在首轮与终轮各查一次 |

**新增章节（建议直接可用）**

1. `## 机械闸（P0，必须，不派 subagent）`
   - 表格 6 项检查 + 每项命令模板 + 失败处理（先修，不派审查）
   - 落地形式：`references/mech-checks.md` + 可选 `scripts/gate_mech.sh`（项目可覆写命令）
2. `## 价值矩阵（P1 只审这五类）`：V1~V5 各自"看什么/判据/必须给的证据"
3. `## 轮次预算与收敛条件`：3 轮上限；A/B 独立收敛；超预算 need-info
4. `## 结论机读格式`：首行 `VERDICT: pass|blocked|need-info`，第二行 `SEV: C= H= M= L=`，第三行 `SCOPE: changed=N out_of_scope=M`，第四行 `EVIDENCE: repro|static`
5. `## 证据分级`：`repro`（构建/仿真/真机可复现）> `static`（grep/read）；最终 `pass` 必须 `EVIDENCE: repro`
6. `## Deviations 闭环`：每条给 `DEV-ID`、理由、影响面、复核轮；复审报告必须列出"待闭环 ID 表"

### 3.2 三个 reviewer 模板

- `streaming-reviewer-prompt.md`（A）
  - 审查范围收敛为 V1/V2/V5，明确"不审命名/风格/注释/测试覆盖"
  - 新增硬要求：**越界清单必须与 `git diff --name-only` 逐项对账**，给出"声明内 N / 越界 M"
  - 口径矛盾必须给"定稿建议"（哪个是唯一口径 + 改哪份文档），禁止只写"存在矛盾"
- `code-reviewer-prompt.md`（B）
  - 删掉"一次性覆盖规范+质量+注释+清理"的四合一，改成 **行为优先**：CRITICAL/HIGH 只收行为类
  - 注释/清理只读机械闸结果：脚本已报的不重复叙述，只报"脚本判不出的语义问题"（注释与行为不一致、术语泄漏的语义判断）
  - 禁止报存量与非本轮；禁止输出逐条格式化/命名清单（归 backlog）
  - 强制"假修复对账"：主 agent 声明的每项修复，逐条给 `已落地 / 未落地 / 无法核对`
- `compact-reviewer-prompt.md`
  - 同步上述收敛；compact 从"两个维度全查"改为"V1~V5 全查 + 机械闸解读"，不再重复注释逐条

### 3.3 相邻 skill 的职责切割

| skill | 现状 | 改成 |
|---|---|---|
| `ddev-comment-gen` | 9 个维度全上 | 维度 1/4/7/8/9 机械项移交脚本；保留 2/3/6（公开 API、结构体枚举、注释与代码一致性） |
| `ddev-clean` | 每轮由 B 输出清单 | 只在终轮/ backlog 阶段跑一次，不进 P1 |
| `ddev-c-pro` | 规范+质量 | 规范类降为 backlog；质量类聚焦 V4 |

## 4. 明确不做（YAGNI）

- 不增加第三个 subagent，不新增审查维度
- 不建历史数据库/benchmark（本次分析脚本够用，放 `/tmp` 即可）
- 不引入"打分/置信度"机制，避免新噪声
- 不改 compact/streaming 的派发方式与提示词裁切规则（这条规则本身没出问题）

## 5. 预期收益（对照分析报告基线）

| 指标 | 基线 | 改造后目标 | 来源 |
|---|---|---|---|
| 每任务派发次数中位 | 10 | ≤4 | 增量复审 + 3 轮预算 |
| 报告注释类条目占比 | ≈65% | ≤20% | 机械闸承接 |
| 结论可机读率 | 79% | 100% | 机读首行 |
| B 报告带 HIGH 比例 | 58% | ≤25% | 只收行为类 + 禁报存量 |
| "已记录/存量"出现率 | 208/140 份 | ≤30 份 | Deviations 闭环 + 默认排除 |
| 父会话中断白跑 | 5.9% | ≤1% | 轮次缩短后的副作用 |

## 6. 落地顺序

1. **Commit 1（流程）**：SKILL.md 新增/改写 6 节 + 三个模板收敛 + 机读格式。零脚本依赖，立刻生效。
2. **Commit 2（机械闸）**：新增 `references/mech-checks.md`，把注释 9 项/卫生 4 项/范围对账写成命令模板；先在 V85X 实跑 2 个真实任务校准误报。
3. **Commit 3（相邻 skill）**：comment-gen / clean / c-pro 的职责切割。
4. 用 3 个真实任务回归，对比第 5 节指标；未达标再调阈值。

## 7. 风险

- 机械闸若命令模板写死项目路径，会降低跨项目复用性 → 模板用占位符 + "项目根 `AGENTS.md` 可覆写命令"。
- B 收敛范围后可能漏掉"非行为但真实"的问题 → 用 backlog 兜底，终轮统一过一遍，不阻塞。
- A 复跑条件收窄后，若清理改动了架构面（少见）可能漏审 → 用"触及架构面文件白名单"判定，宁可多跑 A。
