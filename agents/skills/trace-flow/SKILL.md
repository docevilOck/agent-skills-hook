# trace-flow — 调用链追踪

## 触发

用户显式触发：
- "trace 一下 X"
- "查一下 X 的链路"
- "X 在哪被解析/调用/处理"

不受 `skill-forced-eval` 自动匹配，不需要每次请求都评估。

## 工具

工具选择走 `tool-routing`，本 skill 只管思路。

## 三条铁律

### 1. 碰壁换向

当前方向遇到以下情况时，立即从另一端重新追：
- 闭源库 / 预编译 `.a` / 无源码
- `codegraph_callees` 返回空或全在不可读路径
- 上一步的结论依赖"可能是""看起来像"

换向 = 反向往上追不动就正向往下，反之亦然。

### 2. 远端闭环

从两个端点各自出发，直到两条链路能对接上：

```
入口点 → ... → 汇合点 ← ... ← 出口点
```

汇合不上 = 没定位完。继续查或汇报缺口。

### 3. 单轮上限 5 步

5 次 codegraph 调用还没闭环，先汇报已有链路和缺口，再决定是否继续。防止死追一个方向。

## 禁止行为

- 靠文件名匹配推断调用关系（`esc_` 开头不代表 ESC 仿真调了它）
- 靠目录归属推断使用范围（枚举/宏/类型在 TSPL 目录定义 ≠ 只有 TSPL 用；`pl_exec.h` 的枚举被 ESC/ZPL/EPL/DPL 协议共用）
- 从中间符号反向拼链不验证
- 链路里出现闭源库还继续往下编
- 一个方向追不到底也不知道换方向

## 输出格式

```
入口 → ... → 汇合点 ← ... ← 出口

[每一步的文件:行号，验证工具]
[缺口说明，如有]
```
