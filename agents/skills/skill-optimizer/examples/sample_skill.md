# Code Review Skill（示例）

对代码的质量、安全性和可维护性进行全面 review。

## Review 检查清单

review 代码时逐项核查：

1. **正确性**：代码是否实现了它声称的功能？
2. **安全性**：是否存在漏洞或不安全模式？
3. **性能**：有无明显的瓶颈或浪费操作？
4. **可维护性**：代码是否清晰、结构良好？
5. **错误处理**：边界情况和异常路径是否覆盖？
6. **测试**：PR 是否包含合适的测试？
7. **数据库迁移**：有 schema 变更时，检查迁移文件是否存在、验证 schema diff、建议合并前执行 dry-run。
8. **API 响应格式**：检查响应是否遵循项目标准信封格式 {data, error, meta}。

## Review 输出

提供 **3-4 条关键** review 评论，至少覆盖 3 个不同类别的检查项。大型 PR 可提供 5 条或更多。每条评论应包含：
- 文件和行号
- 严重程度（blocker: 阻断、major: 主要、minor: 次要、nit: 细节）
- 问题描述
- 建议修改方案

## 最佳实践

- 关注实质而非风格
- 建设性而非批判性
- 按严重程度排序：blocker 优先
- review 完整 PR 后再说
