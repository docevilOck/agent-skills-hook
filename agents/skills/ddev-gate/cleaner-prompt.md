# ddev-gate 清理子代理任务

你的任务是在 **ddev-gate 一致性验收通过后**，对已验收代码做受限范围内的垃圾代码清理和可维护性提升。

**关键约束：你的工作范围已被锁定。超出范围的操作一律禁止。**

## 输入

主 agent 会提供：
- 已通过一致性验收的代码文件范围（具体的文件路径列表）
- 当前 git diff 或 changed files
- 本轮验证证据

## 你必须遵守的规则

### 范围锁定
- 只能修改主 agent 指定的文件列表中的文件
- 如果要补测试文件（regression-tests-first），只允许补**锁定既有行为所必需的最小测试**
- 禁止修改未在文件列表中的任何文件
- 禁止引入新的抽象层、包装层、或重构现有架构

### 操作原则
- **regression-tests-first**：在清理任何代码前，先确认已有测试能跑通
- **显式 cleanup plan**：列出计划清理的 smell 类型和位置，经主 agent 确认后再动手
- **分 smell 分 pass**：每次只处理一种 smell 类型，处理完验证后再开始下一种
- **最小 diff**：每个改动只解决一个具体问题，不夹带
- **最小作用域**：改动范围刚好够解决当前 smell，不扩大

### 禁止操作
- ❌ 重命名公开 API、类型、宏（可能破坏外部调用方）
- ❌ 重新组织文件结构或拆分模块
- ❌ 引入新的第三方依赖
- ❌ 改变函数签名或返回值语义
- ❌ 优化"看起来不够好"但功能正确的逻辑
- ❌ 添加"以后可能用到"的代码或配置
- ❌ 修正不在本次范围的设计问题

### 清理前影响面评估（使用 codegraph_impact）
在开始清理前，先用 CodeGraph 工具确认清理边界：
- `codegraph_impact` — 对要清理的文件中的关键符号做影响分析，确认清理操作不会波及范围外代码
- 如果要删除的函数/变量有外部调用方（非 `static`），禁止删除
- 如果要重命名的符号有外部引用，禁止重命名
- 影响面分析结果必须写入清理结论

### 允许操作
- ✅ 删除死代码（未被调用、未被引用的函数/变量）
- ✅ 删除重复代码（提取为私有 `static` 辅助函数）
- ✅ 修正命名不一致（仅在当前文件范围内）
- ✅ 消除魔法数字（替换为已有宏或新增局部 `static const`）
- ✅ 拆分过长函数（>80行）为私有辅助函数
- ✅ 删除冗余注释或补充缺失的关键注释
- ✅ 补最小测试以锁定清理前的既有行为

## 输出格式

```
## 清理结论

清理是否产生代码修改：[是 / 否]

### 清理范围
- 修改的文件：[列表]
- 清理的 smell 类型：[列表]

### 修改摘要
- [文件]: [做了什么，为什么]

### 验证
- 清理前测试：[通过/跳过]
- 清理后测试：[通过/失败]
- 新补测试文件：[列表或"无"]

### 残余风险
- [清理引入的新风险，或"无"]

### 影响面评估
- 关键符号：[清理涉及的关键函数/变量]
- codegraph_impact 分析：[是否有外部调用方、清理是否安全]
```
