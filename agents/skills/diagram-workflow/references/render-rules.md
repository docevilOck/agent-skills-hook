# 渲染规则

## 源文件和渲染文件

- `.puml` 是唯一源文件
- `.md` 是渲染结果
- 两个文件要同目录、同 basename
- 调整图时，默认同时维护 `.puml` 和 `.md`；不要把 `.md` 当成可选产物
- 只要 `.puml` 变了，就必须同步更新 `.md` 中对应的展示图
- 不要为了“修对齐”直接改渲染后的 ASCII

## 什么时候整份刷新，什么时候只替换图块

- 纯图展示文档：可以整份刷新 `.md`
- 带正文的图文档：只替换对应的 text/ASCII 图代码块，以及必要的 `Source:` 行
- 除非用户明确要求，不要因为图更新就重写同文件中的分析说明、结论、表格或备注

这里的“纯图展示文档”通常指只包含以下内容：

1. 标题
2. 一句话用途说明
3. `Source:` 标注
4. ASCII 图代码块
5. 极少量备注

如果 `.md` 超出上述范围，默认按“带正文的图文档”处理。

## 缺文件时怎么处理

- 只有 `.puml`：补建同名 `.md`，并写入 text/ASCII 展示图
- 只有 `.md`：先补齐同名 `.puml`，再刷新 `.md`
- 两者都存在：本次改动后必须同步检查 `.md` 中的 text/ASCII 图是否仍然正确

## 完成判定

以下条件同时满足，才算图已更新完成：

- `.puml` 已更新
- `.md` 中的 text/ASCII 图已同步更新
- `Source:` 标注正确
- 文本说明没有引用旧结构、旧节点名或旧流程

## 文件命名

- 文件名使用 `YY-MM-DD_name.puml`
- 文件名使用 `YY-MM-DD_name.md`
- 同一组图文档保持同名配对

## Markdown 排版

建议按这个顺序写：

1. 标题
2. 一句话说明用途
3. ASCII 图，放在 fenced code block 里
4. 必要时再补一小段说明或小表

## 可读性

- 标签要短，但必须有语义
- 一张图只回答一个问题
- 图一旦开始拥挤，就拆成多张
- ASCII 是默认输出
- SVG 只在确实有帮助时作为补充
