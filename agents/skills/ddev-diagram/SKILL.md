# 画图方法

## 作用

所有图文档共用的画图方法。业务 skill 只负责说"画什么"，这里负责说"怎么画"。

如果上游来自 `ddev-spec`，默认就是把已写出的实现架构文档细化成图，不重新讨论架构本身。

如果上游来自 `ddev-plan`，默认就是把已确认的计划画成支持执行的图，不反过来改计划目标。

## 基本规则

- **唯一产物：`.md` 文件**，图写在 fenced code block 里
- **默认 Mermaid**：能用 Mermaid 表达就用 `mermaid` 代码块
- **退回 Unicode 框图**：Mermaid 表达不了或表达失真时，才手写 Unicode 制表符框图（`text` 代码块）
- **不回退到 ASCII 拼接**：退回路径只用 Unicode 制表符（`┌─┐└┘│├┤┬┴┼`），禁止 `+---+`
- **不再经过 PlantUML**：AI 直接手写图，不出 `.puml` 中间文件
- **一个 code block 只用一种语法**：不在同一个图块里混排 Mermaid 和手写框图
- 文件名格式：`YY-MM-DD_name.md`
- 图文档按固定布局组织（标题 → 用途说明 → 图 → 补充说明）

## 默认动作

用户表达以下任一意图时，直接在 `.md` 中操作：

- 新建图
- 修改图
- 调整结构、连线、节点、布局、文案

执行顺序：

1. 确定图文档位置和文件名
2. 判图型、定语法（见「输出选择」）
3. 画图到 `.md`
4. 补齐标题、用途说明、补充说明
5. 跑「绘制完成门禁」

## 输出选择（先判图型，再定语法）

| 要表达的东西 | 首选 | 退回 Unicode 框图的条件 |
|---|---|---|
| 模块边界、依赖方向、接入点 | Mermaid `flowchart` | 需要严格列对齐的并排对照 |
| 主流程、关键分支、异常出口 | Mermaid `flowchart` | — |
| 消息往返顺序 | Mermaid `sequenceDiagram` | — |
| 状态迁移、生命周期 | Mermaid `stateDiagram-v2` | — |
| 数据结构形状、继承 | Mermaid `classDiagram` | — |
| 表结构、实体关系 | Mermaid `erDiagram` | — |
| 改动前后对照 | Mermaid 两张 `flowchart`（复用同节点名） | 需要逐行严格并排比对 |
| 磁盘 / 内存 / 寄存器 / 协议帧布局（按字节或位对齐） | — | **直接退回** |
| 目录树、文件分布 | — | **直接退回**（text 树） |
| Mermaid 渲染后布局错乱、语义丢失 | — | **退回** |

判定顺序：

1. 上表写「直接退回」的，不试 Mermaid，直接用 Unicode 框图
2. 其余一律先写 Mermaid
3. Mermaid 语法正确但布局/语义明显表达不了时，改写成 Unicode 框图
4. 退回时在图下用一句话说明退回原因（如"字节布局，Mermaid 无法保列宽"），不写长篇辩护

## 更新策略

更新 `.md` 时先判断类型：

- **纯图文档**（只有标题、图、极少量备注）：可整份刷新
- **带正文的图文档**（含分析说明、表格、补充备注）：只替换对应图块，不整文件覆盖

默认目标：图跟着改动变，正文保持稳定。

改图型时（如 flowchart 改 sequenceDiagram），连同语言标记一起替换整个 code block，不留半个旧块。

## 图型选择

- 架构 / 边界图：看模块边界、职责分工和主要连接关系
- 接入点图：看现有代码从哪里接入
- 流程图：看主路径、关键分支和异常出口
- 前后对照图：看修改前后行为变化
- 依赖拓扑图：看模块依赖和布局关系

在架构阶段，优先把"架构规划 + 接入点 + 主流程 + 前后对比"这四类图补齐。

# Mermaid 绘制规范

## 语法选择

| 图类型 | 语法 | 方向 / 备注 |
|--------|------|-------------|
| 架构、边界、依赖、接入点、流程 | `flowchart LR` / `flowchart TD` | 横向看依赖，纵向看流程 |
| 时序、消息往返 | `sequenceDiagram` | 先用 `participant` 声明角色 |
| 状态、生命周期 | `stateDiagram-v2` | `[*] --> S1` 表示入口/出口 |
| 类、结构体形状 | `classDiagram` | `+类型 字段` / `+方法()` |
| 实体关系、表 | `erDiagram` | 用基数记号表达一对一 / 一对多 |
| 时间线、里程碑 | `timeline` | 顺序汇报用 |
| 占比 | `pie` | 只在真有比例数据时用 |

主图优先 `flowchart`。能从 `flowchart` 表达就不要换更重的语法。

## 标签与节点

- 节点 id 只用字母数字下划线，语义标签写在 `[]` `()` `{}` 里
- 标签含 `()` `[]` `{}` `:` `,` `;` `&` 时，用双引号包住：`A["parse (new)"]`
- id 避开保留字：`end` `graph` `subgraph` `class` `click` `style` `linkStyle` `o` `x`
- `subgraph` 必须成对 `end`；嵌套时逐层闭合
- 连线标签写成 `A -->|OK| B`，不写在节点里
- 框内换行用 `<br/>`，不要用真实换行
- 注释用 `%%`，不要用 `//` 或 `#`
- 标签可以写中文（Mermaid 自己排版，不存在等宽对齐问题）
- **默认不加 `style` / `classDef` / 颜色**：信息靠结构和标签表达，颜色不承载语义

## 复杂度控制

- 节点超过 15 个或连线开始交叉成网，拆成多张图
- 一张图只回答一个问题
- Mermaid 自动布局不可摆位；需要固定相对位置时说明清楚依赖方向，或改走 Unicode 框图

## Mermaid 完成门禁（强制）

写完每个 ```mermaid 代码块后逐项核对：

| # | 检查项 | 不通过时 |
|---|--------|----------|
| A1 | 首行是合法图类型声明 | 补声明 |
| A2 | `subgraph` 与 `end` 数量配对 | 补 `end` |
| A3 | 节点 id 只用字母数字下划线，且非保留字 | 改 id |
| A4 | 标签含特殊字符时已加双引号 | 加引号 |
| A5 | `[]` `()` `{}` `""` 成对闭合；语法位置无全角标点 | 修正 |
| A6 | 每条连线都对应正文声明过的真实关系，无孤立节点 | 补关系或删节点 |
| A7 | 无 `style`/`classDef`（信息已由结构表达） | 删除或说明理由 |

### 实渲染校验（本机已装，默认执行）

本机已安装 mermaid 渲染器 `mmdc`（`@mermaid-js/mermaid-cli` 12.x + `chrome-headless-shell`，全局可用，任意目录直接调用）。

含 Mermaid 的 `.md` 直接实渲染，不必手工抽取代码块：

```bash
# 把文档里每个 mermaid 块渲染成 SVG，产物落在 -a 目录
mmdc -q -i <doc>.md -o /tmp/mmd-check/out.md -a /tmp/mmd-check

# 需要肉眼看图时出 PNG，产物同样按序号命名：out-1.png、out-2.png…
mmdc -q -e png -i <doc>.md -o /tmp/mmd-check/out.md -a /tmp/mmd-check

# 单张 .mmd 直接出指定文件名
mmdc -q -e png -s 2 -i <one>.mmd -o /tmp/mmd-check/one.png
```

判读规则：

- 退出码非 0，或某个代码块没有对应 SVG 产物 → 该块语法有错，修语法后重跑
- Artifacts 数量应等于文档里 `mermaid` 代码块数量；数不上就是漏渲染
- `.md` 输入的产物带序号后缀（`out-1.svg`、`out-2.svg`…），不是覆盖成单个文件
- 文档里没有 `mermaid` 块时产出 0 个 SVG 是正常的，不算失败
- **实渲染优先于静态自检**：静态自检抓不到 Mermaid 语法错误，两者冲突以实渲染为准

未装 `mmdc` 的环境退回纯静态自检（A1–A7），并在报告里说明未实渲染。

# Unicode 框图（退回路径）

只在「输出选择」判定退回时使用。

## 制表符：用 Unicode，不用 ASCII 拼接

```
❌  ASCII 拼接:
+----+----+
| A  | B  |
+----+----+

✅  Unicode 制表符:
┌────┬────┐
│ A  │ B  │
└────┴────┘
```

| 字符 | 作用 | 字符 | 作用 |
|------|------|------|------|
| `┌ ┐ └ ┘` | 四角 | `├ ┤ ┬ ┴ ┼` | T 型 / 十字 |
| `│` | 竖线 | `─` | 横线 |
| `► ▼ ▲ ◄` | 实心箭头 | `▷ ▽ △ ◁` | 空心箭头 |

## 先定列宽，再画框

同一列所有框宽度必须一致。先扫内容取最长标签，加边距后统一使用。

```
列宽 = max(框内最长行宽度) + 2   // 左右各留白一格
```

## 先定总宽，再排多列（多列框 + 连线标注图）

多列并排或带连线标注的图，先算后写，不要边写边数空格：

1. **先定总宽 W** — 一次算清全图所有行的最大需求宽度（各列占位宽 + 列间距 + 两侧留白），整图统一用这一个 W
2. **所有行右侧补齐到 W** — 边框行、横向连线行、标签行都补行尾空格到 W，使「所有含 `│` 的行等宽」天然成立；不靠肉眼对齐
3. **框和列用固定列偏移** — 先定每列起始列号（如 `col1=0`、`col2=24`、`col3=48`），框、竖线、转弯、箭头都从这些列号出发
4. **连线标签受剩余宽度约束** — 写标签前算 `剩余宽度 = W - 标签起始列 - 右侧留白`；放不下时优先拆成两行或缩短标签，不向右撑超 W
5. **构造复杂时用一次性 Python 生成器** — 固定 W，逐行 `ljust(W)`，按统一列号定位连线；生成结果只写入 `.md`，不留中间产物

按以上规则构造后，再跑「Unicode 框图完成门禁」的宽度校验。

## 正交连线，禁止斜线

只用横线 `─` + 竖线 `│`，转弯用 `└ ┌ ┘ ┐`。

```
✅  正交:
A ──> B
      │
      v
      C

❌  斜线:
A ──> B
     ╲
      C
```

## 箭头约定

```
──>  右箭头        <──  左箭头
 v   下箭头         ^   上箭头
```

跨行箭头先竖线延伸到目标行再转弯：

```
A ─────────┐
           v
B <────────┘
```

## 短标签原则

框内文字不超过 2 行。详细说明用框外标注或脚注补充。

## 框图标签语言：英文优先

**Unicode 框图 fenced code block 内的所有标签使用英文。** 不在框内写中文。

原因：CJK 字符在等宽字体中的实际像素宽度 ≠ 2× ASCII 宽度（由字体渲染引擎决定，无法通过列宽计算弥补）。在框图中混用中英文会导致视觉错位（"犬牙交错"），且此问题无法通过列宽算法解决。

```
✅  英文标签：
    ┌────────────────┐
    │  flash_test/   │
    │  (new module)  │
    └────────────────┘

❌  中文标签（对齐不可靠）：
    ┌────────────────┐
    │  闪存测试/     │
    │  （新增模块）  │
    └────────────────┘
```

规则：

- 框内标签：英文短词组，用 `_` 或 camelCase 保留代码标识符风格
- 连线/状态/条件文字：英文缩写或短句（如 `OK`、`FAIL`、`count=0`）
- 逻辑复杂、英文表达不清时，才在图外补中文说明（表格或段落）；简单图无需图例
- 此约束只针对 Unicode 框图；Mermaid 块内的中文标签不受限制

### 图外中文说明：解释图意，不是翻译术语

图外中文说明是对图中逻辑、流程或关系的**中文解读**，帮助读者理解"发生了什么"；它不是图中英文术语的中英对照表。

```
✅  正确 — 解释图意：
    > 上电后 bootloader 先校验 flash_test 模块的签名，验签通过才跳转。
    > 如果签名无效，回退到 recovery 分区。

❌  错误 — 翻译术语表：
    | 图中英文        | 中文     |
    |----------------|---------|
    | bootloader     | 引导程序 |
    | flash_test     | 闪存测试 |
    | recovery       | 恢复分区 |
```

规则：

- 图外说明写"流程为什么这样走、关键判断是什么、边界为什么这样画"，不写"这个词对应的中文叫什么"
- 英文术语已在图中出现过的，不需要在说明里重复定义
- 说明短则一两句话，长则分成小段；不写成翻译对照表
- 代码块内已存在的 C/Python 等代码不受此限制（注释中的中文正常保留）

## 一图一事

一张图只回答一个问题。开始拥挤就拆多张。

```
一张图 = 一个视角（边界 / 状态 / 数据布局 / 流程）
```

## 绘制顺序

1. **先摆框** — 多列或带连线标注的图先定总宽 W、列偏移与列宽（见「先定总宽，再排多列」），再确定所有框的位置与尺寸
2. **后连线** — 框定稿后再补 `│` `─` `v` `──>` 等连线
3. **最后补标注** — 框外注释、触发条件、条件文字最后放

---

## 文档布局

图文档按此顺序：

1. 标题
2. 一句话说明用途
3. 图（`mermaid` 或 `text` fenced code block）
4. 需要时补一小段说明或表格

## 绘制完成门禁（强制）

**每次写完或更新含图 `.md` 后，必须执行以下核对。不通过不得视为完成。**

### 步骤

1. **回读文件**：用 Read 工具回读刚写入/更新的 `.md` 文件全文
2. **分流**：按 code block 的语言标记分组 —— `mermaid` 走 A 组，`text`/无标记的框图走 B 组
3. **逐块校验**：A 组跑「Mermaid 完成门禁」，B 组跑「Unicode 框图完成门禁」
4. **任一不通过** → 修正 → 回读重跑，直到全部通过
5. **同一张图修 3 次仍不通过** → 换语法或重画该图

### Unicode 框图完成门禁

#### 宽度自动校验

AI 画完框图后，必须对每个 Unicode 框图执行以下 Python 脚本进行宽度校验：

```bash
python3 -c "
import sys
block = sys.stdin.read()
for i, line in enumerate(block.split('\n'), 1):
    # 跳过空行
    if not line.strip():
        continue
    # ┌─┐ └─┘ ─ 等制表符都是单字符宽，len() 按 Unicode 字符计数是正确的
    w = len(line)
    # 检测右边框位置差异：所有含 │ 的行宽度应一致
    if '│' in line:
        print(f'L{i:3d}  w={w:3d}  {line}')
    elif line.lstrip().startswith(('┌','└','├','┐','┘','┤')):
        print(f'L{i:3d}  w={w:3d}  {line}')
"
```

用法：将框图中整个 fenced code block 的内容复制后 pipe 到该脚本。输出会列出每行的 Unicode 字符宽度 w 和行内容。检查要点：

- 所有含 `│` 的行 `w` 值必须相同 → 否则右边框不齐
- 同框 `┌─...─┐` 与 `└─...─┘` 的 `w` 值必须相同 → 否则上下框线不等宽
- 上框 `w` 与内容行 `w` 的差值 = 2（左右边框各占 1 列），即 `w(border) == w(content)` 且 `w(border) - w(content_with_pipe) == 0`（因为 `│` 就是边框本身，不额外占用边距）

#### 检查项

| # | 检查项 | 方法 | 不通过时 |
|---|--------|------|----------|
| B1 | 右边框对齐 | 先跑「宽度自动校验」：所有含 `│` 的行 `w` 值必须相等（即同一列）；不满足时补/削空格 | 补空格或削空格，重写该行 |
| B2 | 上下框线等宽 | 先跑「宽度自动校验」：`┌─...─┐` 与 `└─...─┘` 的 `w` 值必须相同 | 调整横线数量 |
| B3 | T型/十字接合完整 | `├ ┤ ┬ ┴ ┼` 上下左右邻接位是否有对应连线 | 补连或改T型字符 |
| B4 | 无斜线 | grep `╲ ╱ ╳ ╱` — 必须零命中 | 改用正交转折 |
| B5 | 无断线 | 竖线 `│` 贯穿多行时，每行同一列都有 `│` 或合法转角 | 补竖线 |
| B6 | 无 ASCII 拼接 | grep `+---+` — 必须零命中；竖向边框只允许 `│` | 改 Unicode 制表符 |

#### 示例：右边框对齐检查

```
写入的图（错误 — 第 3 行右边框偏右）:
┌──────────────────────┐
│  AGENTS.md (global)  │
│  session end hook      │  ← 右边框比第 1 行右移了 2 列
└──────────────────────┘

自检发现 → 修正为:
┌──────────────────────┐
│  AGENTS.md (global)  │
│  session end hook    │
└──────────────────────┘
```

## 生成后自检

- 图是否按「输出选择」选了正确语法，退回的是否写了原因
- Mermaid 块是否通过 A1-A7；Unicode 框图是否通过 B1-B6
- 节点名、连线关系、说明文字是否一致
- 是否一图一事，未拥挤
