# 图形方法示例

## 目的

这份示例展示的是：一个图文档应该怎么组织，才适合后续反复维护。

## 文件

- `examples/26-05-03_ddev-diagram-overview.md`

## 文档结构

```markdown
# 图文档标题

## 1. 说明
[一句话说明这张图回答什么问题]

## 2. ASCII 图
[遵循 ddev-diagram 规范手写的 ASCII 图]

## 3. 备注
[必要时补少量说明或表格]
```

## 带正文时的更新方式

如果 `.md` 同时包含展示图、正文分析、分节说明或表格，更新时按下面方式处理：

````markdown
# 模块接入点说明

## 1. 背景
[这里是人工维护的正文，不因图更新而整段重写]

## 2. 当前结构图

```text
[这里只替换当前图块]
```

## 3. 接入点说明
[这里是人工维护的说明、约束或表格，默认保留]
````

这种文档在图更新时，只替换 `## 2. 当前结构图` 下的 ASCII 图代码块，不整份覆盖。

## 示例规则

- 图直接手写 ASCII 到 `.md`，不保留中间源文件
- 复杂图默认手工维护 ASCII，全部遵循 ddev-diagram 规范
- 图有改动时直接重画整张，不局部补丁
- 纯图展示文档可以整份刷新；带正文的图文档只替换图块
- 如果别人看不懂 ASCII，优先重画而不是补长文
